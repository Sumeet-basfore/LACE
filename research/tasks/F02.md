## Research Question
Can a verification-first orchestration layer improve coding-agent reliability enough to justify its additional complexity?

## Scope
Design a reproducible *pilot* experiment (do not jump to large benchmark):

### Baseline: same model + normal single-agent loop
### Candidate: same model + controlled orchestration / verification loop (spec → tests → gate, worktree, parse→feedback)

Keep variables identical where possible. Investigate measurement of:
- task success, tests passing, regression rate, cost/tokens, latency, human intervention, recovery success, repeated-run reliability

Pre-registered decision thresholds (do not manipulate):
- ≥10pp absolute gain, ≤2× median cost/latency, regression no worse, sufficient n for 95% CI

If methodology is flawed, fix before scaling.

EXECUTE small pilot if practical (n≥3–5 tasks via same model) and report results; if not practical, explain why and what would be needed.

## Methodology
Prefer primary papers/specs/repos/docs. For experiment: define tasks (e.g., SWE-bench Verified subset or small synthetic repo), keep model identical, log cost/latency/regression. Do not claim improvement without measuring it. Cite. Distinguish labels. Handle contradictions. Report missing evidence as "No reliable evidence found."
