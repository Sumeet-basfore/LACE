## Research Question
Are the previously identified coding-agent pains frequent and consequential enough to justify a product?

## Scope (must cover)
Investigate 50–100 GitHub issues where practical + discussions + credible developer reports + community evidence.

Classify into:
- context loss / context management
- hallucination / unreliable edits
- verification burden
- regression
- loops / hangs / stuck agents
- cost / latency
- progress visibility / steerability
- privacy / credential trust

## Required Analysis
1. Which problems recur most often? (in sampled corpus — do not extrapolate to fake population %)
2. Which appear most severe?
3. Which are directly solvable at the harness layer?
4. Which are model limitations vs harness limitations?
5. Is there enough evidence to call one or more product-grade problems?

Explicitly distinguish: prevalence in corpus vs severity vs broader demand. If reliable prevalence cannot be established, say "No reliable evidence found."

## Methodology
Prefer primary sources per skill hierarchy. Use GitHub API issues/discussions (search + repo sampling), official docs, engineering blogs. For sentiment: HN/Reddit via Algolia API as anecdotal only. Record every important source in evidence.md with URL + access date + quote. Cite important claims. Distinguish FACT/EVIDENCE/INFERENCE/HYPOTHESIS/OPINION. 50–100 issue sample preferred; if less, report actual n and limitation.

## Artifacts Required
- `research/F01/report.md` — question, methodology, sample description (n, repos, dates, query), evidence, findings per category, contradictions, confidence, limitations, recommendation
- `research/F01/evidence.md` — source table (URL, type, date, relevance, quote, accessed)
- `research/F01/findings.md` — labeled FACT/EVIDENCE/INFERENCE/HYPOTHESIS/OPINION per category
- `research/F01/open-questions.md` — gaps, unanswered, follow-ups
