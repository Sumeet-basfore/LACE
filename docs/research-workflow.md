## 1. System Architecture & Information Flow

The LACE research environment integrates version-controlled engineering, curated export staging, cloud distribution, and AI-driven interrogation into a unified pipeline:

```
                 LACE GIT
              SOURCE OF TRUTH
                     │
                     ▼
              research/export/
               curated corpus
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
     Google Drive           GitHub repo
          │
          ▼
      NotebookLM
    research brain
          │
          ▼
  questions / synthesis
```

## 2. Layer Definitions & Roles

### A. Git Repository (Canonical Source of Truth)
- **Authority:** The primary, immutable source of truth for all code, experiment protocols, manifests, formal reports, and architectural specifications.
- **Rule:** Nothing is considered project reality until committed (or staged for commit) in the local repository. Ideas discussed in NotebookLM or Slack do not become canon until formally written into `docs/`, `context/`, or `research/reports/`.

### B. `research/export/` (Curated Staging Layer)
- **Role:** A local, version-controlled projection containing strictly Class A canonical research materials formatted for optimal AI retrieval.
- **Separation:** Raw transcripts, provider error logs, and Docker runtime exhaust are strictly excluded to maintain high signal-to-noise.
- **Tooling:** Deterministically populated and verified via `python3 scripts/export_research.py`.

### C. Google Drive (Distribution & Sync Layer)
- **Role:** A shared directory structure (`LACE Research/`) mirroring `research/export/`.
- **Purpose:** Serves as the cloud ingestion bridge for NotebookLM and enables human team members to view research docs in a browser.
- **State:** Manual sync in this environment (no automated API/CLI tokens).

### D. NotebookLM (Research Interrogation & Synthesis Layer)
- **Role:** The AI-powered research brain.
- **Capabilities:** Rapid semantic querying, multi-document synthesis, contradiction detection, and assumption auditing using the prompt pack (`research/export/notebooklm-prompts.md`).
- **Boundaries:** Answers generated by NotebookLM are hypotheses or analytical queries. They must be validated against repository evidence before informing decisions.

### E. Antigravity CLI (Parallel Research / Engineering Worker)
- **Role:** Operates as a parallel research, code analysis, and implementation agent.
- **Boundary:** Writes all findings, code changes, and audit reports directly back to the Git working tree. Antigravity CLI is **never** an independent source of truth.

### F. Cursor / Developer IDE (Repository Engineering)
- **Role:** Local engineering environment for writing code, debugging harnesses, managing Git hygiene, and executing controlled unit tests.

### G. LACE Experiments (Controlled Benchmark Research)
- **Role:** Strict, frozen research evaluations (e.g., Phase 2D SWE-bench Lite runs).
- **Isolation:** Kept completely separate from general research automation. Model parameters (`muse-spark-1.2-contributor-free`), providers (`opencode`), and manifests are frozen and never modified without formal decision review.

## 3. End-to-End Operational Lifecycle

1. **Step 1 — Author / Modify Research:**  
   Engineers and research agents update canonical specifications in `docs/`, `context/`, or `research/reports/`.
2. **Step 2 — Execute Export Pipeline:**  
   Run `python3 scripts/export_research.py`. The exporter validates manifest integrity, filters out raw logs, scans for secrets, and writes clean markdown with provenance headers to `research/export/`.
3. **Step 3 — Inspect Diff & Commit:**  
   Inspect the staged export diff (`git diff -- research/export/`) to ensure deterministic output.
4. **Step 4 — Mirror to Google Drive:**  
   Copy updated files from `research/export/` to the matching folder in `LACE Research/` on Google Drive.
5. **Step 5 — Interrogate in NotebookLM:**  
   Refresh sources in NotebookLM and execute queries from `notebooklm-prompts.md` to stress-test claims, audit contradictions, and formulate new hypotheses.
6. **Step 6 — Record Decisions:**  
   Synthesize insights from NotebookLM and record concrete choices in `context/decisions.md` in Git.
